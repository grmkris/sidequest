# G1e manual acceptance on prod-testnet

**Decision (Kris, 8 October 2026):** no A01–A08 fixture reruns. Kris tests G1e by hand after the orchestrator releases
and verifies it. The retained G1d fixture receipts remain historical evidence, superseded by G1e. The harness changes
below are planned support for the required bond; they are not authorization to execute it.

Mainnet requires separate explicit approval and genuine-user acceptance evidence. Each record names source commit,
generation, network, origin, fixture or genuine user, result, receipts and any remaining limits. Unit and fork checks
remain separate from live proof.

## Before the session

1. Verify both stages are on Monad testnet (10143), writes open, and the integrated G1e SHA passed the release gates.
2. Read `minimumCreatorBond`, `MAX_MINIMUM_CREATOR_BOND`, `unfilledForfeitBps`, `CANCEL_GRACE` and the current
   `FeeSchedule.treasury()` live. Initial testnet floor is 10 SIDE, cap 1,000 SIDE, rate 2,500 bps and grace 600 seconds.
3. Claim test tokens: the faucet gives at least 1,000 SIDE per claim. Kris stakes enough SIDE behind the creator wallet
   for every simultaneous publish. Each publish requires at least the live floor, separately from reward and gas.
4. The operator backs the registered agent wallet through **Back this agent** before A03/A04. The operator owns that
   position; the agent cannot withdraw it. Confirm available backing and ownership from chain state. Four simultaneous
   planned harness publishes need four floor bonds; top up from the faucet before setup if the operator lacks SIDE.
5. Preserve frozen operation keys, browser transaction journals and receipts. A lost response reuses the original key
   and exact arguments. New G1e plans never reuse the G1d binding, grants or signed bytes.

## Unfilled bond checks

Publish distinct never-activated jobs using the live floor. Record `publishedAt`, the snapshotted forfeit rate, exact bond,
receipt block timestamps, treasury and backing before each action. A chosen worker who never activates still counts as
unfilled; selection alone does not avoid the forfeit. There is no posting fee.

- Cancel strictly before `publishedAt + CANCEL_GRACE`: the whole creator bond releases, treasury delta is zero and no
  `BondForfeited` occurs. The 599-second boundary is a labelled unit/fork proof; a live transaction must confirm in time.
- Cancel at or after `publishedAt + CANCEL_GRACE`: `bond * snapshotBps / 10000` goes to the current Safe treasury.
  Confirm the exact token transfer, remainder release, vault accounting and indexed `BondForfeited`. Initial 10 SIDE
  and 2,500 bps produce exactly 2.5 SIDE forfeited and 7.5 SIDE released.
- Let a never-activated listing expire, then settle: the same forfeit occurs even after expiry. Record that as the
  explicit unfilled-listing exception; activated jobs retain the no-penalty-at/after-expiry rule.
- Label Safe setter/cap, 599/600 boundary, queued backing, treasury rotation and rate-snapshot checks as unit/fork unless
  an exact additional live step is approved. Policy changes apply only to new listings.

Also record directory advertise/withdraw, hosted testnet `x402_pay`, an invite accepted by a worker, the Goblin showcase,
and the vault's fair-exit flows. These remain separate from the stopped G1d fixture suite and startup-only arbiter proof.
