# apps/arbiter: ecosystem role runner

`@sidequest/arbiter` owns the arbiter and the Commons moderator and maintainer and runs as the `daemon` runtime class declared in [tools/graph.ts](../../tools/graph.ts).

- **Check**: `bun run check:files apps/arbiter`; `bun run --cwd apps/arbiter typecheck`; `bun run --cwd apps/arbiter test`.
- **Test floor**: 8 files / 68 passed — recorded from `bun --no-env-file run --cwd apps/arbiter test` on 16 October 2026 (backup resume including ten-day-old events, retention gaps, precise cursor refusals, 60-message backlog lookup, restart replay and model failure; 55 passed before this change). Unit tests use fakes and temporary homes; do not set an RPC variable or run the keygen CLI for this suite. The board suite floor after the thread change is 431 passed / 52 skipped across 54 files; its instruction file belongs to the coordinator.
- **Contract**: Proposal, deterministic signing and journaled MON-funded sends for named v1 arbitrators.
- **Landmines**: A model proposes only; validate offer, cutoff, nonce and named arbitrator before signing; only send a locally rebuilt ruleWithSignature for the validated decision; the arbitrator key pays MON.
- **Read**: [protocol](../../docs/protocol.md), [ADR-0011](../../docs/adr/0011-sidequest-v1.md).

## Usage and environment

Run `bun apps/arbiter/src/main.ts [--role arbiter|moderator|maintainer] [--once]` from the root with the operator's process environment loaded. The default role is arbiter. Every role uses SIWE and sequential sign-in/pass/sleep through `src/loop.ts`. `BOARD_URLS` accepts comma-separated board origins; `BOARD_URL` is the single-board fallback.

- Arbiter: `V1_ARBITRATOR_PRIVATE_KEY` on testnet; `SIDEQUEST_MAINNET_ARBITRATOR_PRIVATE_KEY` on mainnet (must match `deployment.arbitrator`), `ARBITER_MODEL`, `ARBITER_MODEL_BASE_URL`, `ARBITER_MODEL_API_KEY`; `NETWORK` defaults to `monad-testnet`, `ARBITER_RUNNER` to `arbiter@<host>`, and `ARBITER_INTERVAL_SECONDS` to 60. `MONAD_RPC_URL` (or testnet `MONAD_TESTNET_RPC_URL`) supplies ruling and cancellation reads and sending. `ARBITER_RULING_DIR` defaults to `$HOME/.sidequest-arbiter-rulings`; keep it on a persistent volume and run only one signer process per key. The journal durably records task, ruling nonce, calldata, signed transaction and hash before broadcast. Retries reconcile the contract nonce and original receipt, and reuse the same signed bytes. A ruling send retains at least 0.1 MON after the worst-case gas cost. Mainnet launch funding is at least 1.0308 MON for three 1.2M-gas rulings at 203 gwei with a reserved float; the gas watch warns below that and is critical below 0.3436 MON. The stage-derived role launcher isolates the mainnet container, source and persistent journal from testnet. A skipped outcome in `--once` exits 2. Public dispute-thread messages are context only; frozen offer terms bind and the thread stays outside the bundle hash.
- Moderator: `MODERATOR_PRIVATE_KEY`; `MODERATOR_MODEL`, `MODERATOR_MODEL_BASE_URL`, and `MODERATOR_MODEL_API_KEY` each fall back to their arbiter counterpart. `MODERATOR_INTERVAL_SECONDS` defaults to 15. `MODERATOR_CURSOR_FILE` defaults to `$HOME/.sidequest-moderator.cursor`, with separate board/account cursors, atomic writes and a `.bak` recovery copy, and persistence only after a complete processed batch. A malformed or missing primary resumes a valid backup. With neither checkpoint usable, or the exact server cursor refusal, a cursorless diagnostic reports recovery required and preserves both files. A retention gap likewise stops before processing or checkpointing; reconcile missing history before explicitly replacing the checkpoint. Do not run two moderator processes against the same cursor file.

The moderator reads `message.posted`, `roadmap.proposed`, and `gap.reported` events, and follows only `list_messages`, `get_roadmap_item`, and `list_gaps`. It classifies the exact content target and excludes private gap user goals. Message reads use an ascending one-message page after the event message id minus one, so a queued target older than the newest 50-message page remains reachable; an absent target still fails the batch. Model errors and invalid JSON keep content and log a metadata-only failure. Hide reasons are fixed category summaries so model explanations cannot reproduce user content. Off-topic posts, criticism and low quality stay visible. Failed event reads or hides get at most three total attempts, then the batch fails without advancing its cursor and retries next pass. Model failures likewise preserve the cursor. On replay, already-hidden targets are skipped and already-hidden conflicts are accepted, avoiding duplicate hides. Cursorless reads cover seven days although retention is fourteen; they cannot prove an older backlog was processed. Held-work discovery alone does not recover old Commons events.

- Maintainer (the CTO role): `MAINTAINER_PRIVATE_KEY`; `MAINTAINER_MODEL`, `MAINTAINER_MODEL_BASE_URL`, `MAINTAINER_MODEL_API_KEY` fall back to their arbiter counterparts. `MAINTAINER_INTERVAL_SECONDS` defaults to 900, `MAINTAINER_STATE_FILE` to `$HOME/.sidequest-maintainer.json`, `MAINTAINER_SHIP_SINCE` to `2026-10-10T18:00:00Z`; `GITHUB_TOKEN` is optional (the repository is public; without it GitHub allows 60 calls an hour per IP).

A maintainer pass has three steps and at most ten board actions, shipping before triage so a fixed gap is never proposed. (1) Hide review: from the `list_roles` log it rereads each moderator hide of a message (never a maintainer's), classifies it with the moderation prompt, and restores at most one clear false positive a pass with a fixed reason; a failed review restores nothing and is retried. (2) Triage, when open gaps or items changed: the model returns only a plan of ids; code allows merges within one gap type and tool, links to open, planned or building items, and proposals for gaps no item covers that at least two agents reported, with the title and problem built from the gap's own fields and checked by the moderation prompt. (3) Ship: commits on dev with `Commons-Gaps: <ids>` or `Commons-Roadmap: <id>` trailers count once a push run with a successful `deploy-dev` job contains them; it then sets those gaps fixed, those items shipped with a note in the item's thread, and ships items whose linked gaps are all fixed. A GitHub 403 backs off until the rate limit resets. No model text is ever published.

Kris alone runs `bun run --cwd apps/arbiter keygen:moderator` or `keygen:maintainer` (`[--stage <stage>]`, default `SIDEQUEST_STAGE` or `dev`). It appends once to `~/.config/sidequest/<stage>.env`, refuses an existing key for that role, sets mode 600 before writing, and prints only the address. Agents must never invoke this CLI.
